# 动作状态机与输入仲裁 · 需求说明

> 用途：交给设计方重新规划动作状态机与输入仲裁。本文只描述**问题与需求**，不预设实现。
> 现状代码：`src/locomotion/domain/loco_action_machine.gd`、`src/presentation/input_adapter.gd`。

## 1. 背景

- 2.5D 清版动作游戏，逻辑固定 60 Hz（`GameConstants.TICK_DELTA`），渲染帧与逻辑步不是 1:1。
- 玩家操作：移动（连续）、攻击 / 跳跃 / 冲刺（按下沿）、技能（4 槽）、格挡（按住）。
- 攻击是三段连击，每段有起手 / 判定 / 收招三个相位，时长来自图集（约 0.6~1.0 秒一套）。
- 输入在渲染帧锁存，逻辑步消费（`InputAdapter.capture/poll`）。

## 2. 已确认的缺陷（实机反馈 + 逐帧复现）

用户原话：

> 「我按了攻击和移动，结果我都停下来了还在攻击，而且我们的攻击居然还能缓慢移动，这完全就是 bug！！！」

逐帧复现（`LocoActionMachine` 直接驱动，60 Hz）：

| # | 场景 | 实测结果 | 判定 |
|---|---|---|---|
| D1 | 攻击一次，之后一直按住方向右 | 0.72 秒内滑出 **0.86 m**（攻击中按 `attack_move_multiplier=0.2` 持续位移） | **bug**：攻击期间不应因方向输入产生位移 |
| D2 | 攻击中连按三下攻击 | 打满三段（连段队列是计数，会累计） | **bug**：玩家停手后角色还在打 |
| D3 | 同一帧按攻击 + 跳跃 | 攻击先出，跳跃被延迟到攻击结束（0.72 秒后）才执行 | **bug**：像幽灵输入 |
| D4 | 攻击起手那一帧 | 曾以全速滑出 0.10 m（已修，但说明位移路径不可靠） | 已修 |
| D5 | 起手阶段按冲刺 | 旧版直接丢失（0.12 秒缓冲短于动作时长） | 旧 bug；现用 0.8 秒待执行队列缓解，但引出 D2/D3 |

## 3. 硬性需求

### MUST

- **R1 攻击期间零位移。** 方向输入不得改变平面坐标。允许每段攻击自带固定突进（数据驱动、与输入无关），但不得随按住方向持续移动。
- **R2 输入即动作。** 玩家没按的动作不得被执行。松开所有键后，角色最多在当前动作的自然结束点停下，不得因为队列继续接下一段。
- **R3 连段不得累计。** 一次按键最多预约**一段**下一段；连续快速按多次不得叠成自动连段。
- **R4 状态必须显式声明输入契约。** 每个状态（IDLE/RUN/JUMP/FALL/LAND/DASH/ATTACK/SKILL/HURT/DEAD）写明：接受哪些输入、拒绝哪些输入、拒绝的输入是**丢弃**还是**保留**、保留多久。
- **R5 同一帧多键的优先级必须写死**，并保证结果可复现。
- **R6 取消窗口必须写死。** 攻击/技能/冲刺/受击各自能否被移动、冲刺、跳跃、技能取消，以及在哪一段可取消。
- **R7 每条规则都要能逐帧自动化测试**（给输入序列 → 断言状态/位移/段数）。

### MUST NOT

- 不得让「锁定期间按下的键」在很久之后自己触发（当前 `_pending` 保留 0.8 秒，是 D2/D3 的直接来源）。
- 不得用「时间缓冲窗口」去覆盖比窗口更长的动作（当前缓冲 0.12 秒，攻击 0.6~1.0 秒）。
- 不得让方向输入在攻击/受击/施法期间改变坐标。

## 4. 现状机制与问题定位

| 机制 | 位置 | 问题 |
|---|---|---|
| `attack_move_multiplier = 0.2` | `loco_action_machine.gd:47`，用于 `_update_attack` `:338` | D1：攻击中按方向持续位移 |
| 连段计数 `_combo_queue` | 声明 `:84`，累加 `:184`，消费 `:376-383`、`:401-409` | D2：多次按键累计成多段，停手后继续打 |
| 待执行队列 `_pending` | 声明 `:88`，`_carry_unconsumed_input` `:196-204`，`_take_action` `:470-477` | D3：没被消费的键保留 0.8 秒，之后自己触发 |
| `PENDING_WINDOW = 0.8` | `:22` | 保留时间远超一套攻击，主观上就是「按了过一会儿才动」 |
| 输入缓冲 0.12 秒 | `input_buffer.gd`，`GameConstants.INPUT_BUFFER_WINDOW` | 短于动作时长，锁定期间的按键会丢（旧 bug） |
| 起手清零速度 | `_update_ground` | D4 的修复；攻击中仍会重新加速到 0.2 倍 |
| 技能状态门 | `actor_runtime.gd::_can_start_action` | 攻击/受击中不能放技能（上一版砍掉，需确认是否保留） |

## 5. 需要设计方决策的问题

> 以下是产品取舍，不是实现细节。每条给出当前默认与影响，供拍板。

**Q1 攻击期间的位移**
- A. 完全零位移（用户反馈倾向）。
- B. 每段攻击固定前冲 N 米（数据配置），与输入无关。
- C. 保留输入驱动的低速位移（现状，用户已判为 bug）。

**Q2 连段预约**
- A. 只预约一段，且按键必须发生在当前段结束前 0.2 秒内（控制最强，早期乱按无效）。
- B. 只预约一段，任意时刻按下都算（乱按会多打一段，但不会打满三段）。
- C. 计数队列，连按三下打三段（现状，用户已判为 bug）。

**Q3 攻击的承诺程度**
- A. 一旦起手必须播完，松开攻击键不取消（承诺制）。
- B. 收招段可被移动/冲刺取消。
- C. 任何阶段都能被移动取消（最灵活，但攻击无责任）。

**Q4 同一帧多键的优先级**
- 候选：攻击 > 跳跃 > 冲刺 / 冲刺 > 跳跃 > 攻击 / 技能 > 其它。
- 需要明确：输的那个键是丢弃，还是保留到下一个可执行点、保留多久。

**Q5 锁定期间按下的其它键**
- A. 直接丢弃（宁可「没按上」，也不要「过一会儿自己动」）。
- B. 只保留一个动作，最多 0.15 秒。
- C. 保留 0.8 秒（现状，导致 D3）。

**Q6 攻击后摇的取消**
- 冲刺取消（上一版已加）是否保留？跳跃/移动能否取消？

**Q7 技能与格挡**
- 技能能否取消攻击/后摇？格挡在攻击/冲刺中是否生效（上一版改成不生效）？

## 6. 建议的输入语义表（供设计参考）

| 当前状态 | 攻击键 | 跳跃键 | 冲刺键 | 方向键 | 技能键 |
|---|---|---|---|---|---|
| IDLE/RUN/LAND | 起手攻击 | 起跳 | 起手冲刺 | 移动 | 起手技能 |
| JUMP/FALL | 空中攻击 | 土狼时间内可跳 | 空中冲刺（待定） | 空中控制 | 起手技能（待定） |
| ATTACK | 预约下一段（受 Q2 约束） | 丢弃或短保留（Q5） | 收招取消（Q6） | **忽略**（Q1） | 拒绝（Q7） |
| DASH | 冲刺结束后执行（短保留） | 冲刺结束后执行（短保留） | 忽略 | 忽略 | 拒绝 |
| HURT | 丢弃 | 丢弃 | 丢弃 | 忽略 | 拒绝 |
| SKILL | 丢弃 | 丢弃 | 丢弃 | 忽略 | 拒绝 |

## 7. 验收用例（逐帧、可自动化）

- **A1 攻击零位移**：攻击后按住右 60 帧，`plane_pos.x` 变化 ≤ 0.001 m。
- **A2 松开即停**：按一次攻击，之后无输入，播完当前段后必须回到 IDLE，不得接第二段。
- **A3 连段上限**：按一次攻击后在起手/判定/收招各按一次，最多只出一段额外攻击（按 Q2 的最终选择断言）。
- **A4 无幽灵输入**：攻击起手时按跳跃，若 Q5 选丢弃，则攻击结束后不得起跳；若选短保留，则只在 0.15 秒内有效。
- **A5 优先级**：同一帧按攻击+跳跃，断言最终先进入哪个状态（按 Q4 的最终选择）。
- **A6 取消窗口**：后摇按冲刺，断言是否进入 DASH（按 Q6）。
- **A7 锁定期间方向键**：受击/施法/冲刺中按住方向，坐标不变。
- **A8 动作结束恢复移动**：攻击结束后的下一逻辑步，按住方向必须恢复全速移动。

## 8. 不在本文范围

- 攻击判定盒与图集同步、命中窗口（已有实现与测试）。
- AI 输入（AI 直接产出 `LocoInputFrame`，与玩家共用状态机）。
- 技能数值、格挡耐力消耗（尚未实现）。

---

**结论（给设计方的约束摘要）**：攻击是承诺动作，期间不接受方向位移；输入不得排队超过一个动作，且不得累计连段；每个状态的输入契约、优先级、取消窗口必须显式写死并可用逐帧用例验证。

## 9. 实现状态（2026-10-30）

已按设计方案落地：

- 三层拆分：`InputAdapter`（锁存）/ `InputContract` + `IntentArbiter`（仲裁）/ `MotionMode`（运动）。
- 攻击期间零位移由 `MotionMode` 结构保证；`attack_move_multiplier`、`InputBuffer`、
  `INPUT_BUFFER_WINDOW`、`_combo_queue`、`_pending`、`_carry_unconsumed_input` 已删除。
- 单槽预输入（9 tick，锚定可执行时刻）；连段是单 bool link，最多额外一段；
  收招后半段可被冲刺/跳跃/技能取消；方向键不能取消攻击。
- 空中攻击水平速度清零；空中冲刺 / 空中技能 v1 关闭。
- A1~A8 均有逐帧用例（`tests/unit/locomotion/test_loco_action_machine.gd`）。

与设计稿的偏差（待确认）：

1. **整数 tick**：相位与窗口按 tick 量化（四舍五入到 1/60 秒），但计时器仍以 float 秒存储。
   游戏固定 60 Hz 推进，行为等价；完全整数化会牵动全部用可变 dt 的测试，暂缓。
2. **技能仲裁位置**：技能仍在 `ActorRuntime` 里先于动作机执行（优先级由执行顺序保证），
   动作机的 `IntentArbiter` 只负责 冲刺 > 跳跃 > 攻击。技能预输入（B(9)）未实现：
   技能取消只在其窗口已经打开时生效。
3. **A8 时序**：动作在第 N tick 结束，第 N+1 tick 就恢复全速移动（设计稿写 N+2）。
   早一帧更跟手；如需严格 N+2，在 `_finish_attack` 后加一拍过渡。
